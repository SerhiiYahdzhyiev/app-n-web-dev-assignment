# 11. CI/CD и GitOps

[Маршрут](../lab-sequence.md) · Нужно: 07, 09–10 · Далее: [12](12-index-state.md)

## Цель
Выпускать проверяемые версии без ручного редактирования работающих контейнеров.

## Задание
1. Настрой pipeline: необходимые проверки → сборка → registry → обновление версии в конфигурации.
2. Раздели app manifests и различия окружений через Kustomize. Не создавай полноценные дубликаты тяжёлого стека без ресурсов.
3. Добавь Argo CD и явную модель доступа к кластеру/registry.
4. Настрой хранение секретов вне plaintext Git, например SOPS с выбранным механизмом расшифровки. Документируй восстановление ключей.
5. Свяжи deployed version с metrics/logs и отметкой rollout на графиках.

## Эксперименты
Выкати версию с неуспешной readiness; внеси ручной drift; выполни откат под baseline-нагрузкой. Проверь поведение GitOps, а не только kubectl rollout undo.

## Приёмка и артефакты
Новая версия проходит воспроизводимый путь до кластера; неправильный релиз обнаруживается и откатывается; drift имеет предсказуемую судьбу. Из Git виден желаемый digest/tag, а не изменяемый `latest`. Секреты и ключи расшифровки не попали в репозиторий.

## Подсказки
Immutable images, reconciliation, Git revert vs imperative rollback, deployment health. Откат приложения не откатывает данные: миграции expand/contract проверить в 15.

Рубежи: CI → registry → GitOps → secrets → rollback.
