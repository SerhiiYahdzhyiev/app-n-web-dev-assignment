# 09. Диски, резервные копии и восстановление

[Маршрут](../lab-sequence.md) · Нужно: 06–08 · Далее: [10](10-capacity.md)

## Цель
Доказать восстановимость данных, а не просто успешное выполнение backup job.

## Задание
1. Классифицируй MongoDB, Redis, FAISS и модель: первичные данные, производные данные, кэш, артефакт.
2. Исследуй local-path PVC: к какой ноде привязан, что будет после удаления pod и потери ноды.
3. Создай backup по расписанию, отдельное хранилище копий и политику retention. Копия должна пережить потерю исходного диска.
4. Восстанови БД в отдельный volume/окружение и проверь контрольный набор записей, связи и пользовательский сценарий.
5. Добавь метрики/alerts: возраст последней успешной копии, результат job, свободное место; измерь длительность восстановления.

## Эксперименты
Останови ноду с тестовой БД. Отдельно восстанови данные при недоступном исходном volume. Удали тестовый кэш и восстанови производный индекс из источника истины настолько, насколько позволяет текущая реализация; обнаруженные проблемы перенеси в 12.

## Приёмка и артефакты
- RPO/RTO определены и измерены; время не ограничивается выполнением команды restore.
- Runbook позволяет восстановить магазин без доступа к исходной БД.
- Backup failure замечен мониторингом; восстановленные данные проверены по содержимому.

## Подсказки
Application-consistent backup, MongoDB backup consistency, reclaim policy, volume node affinity. Snapshot VM не равен согласованной копии приложения. Replication не заменяет backup. Не добавляй распределённое хранилище до понимания исходной проблемы.

Рубежи: классификация → backup → restore → отказ ноды → alert.
