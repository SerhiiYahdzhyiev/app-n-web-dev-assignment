# 01. Воспроизводимый магазин

[Маршрут](../lab-sequence.md) · Далее: [02](02-vm-network.md)

## Цель
Получить проверяемую исходную систему до изменений архитектуры. Исходные условия: текущий репозиторий и локальный Docker Compose.

## Задание
1. Собери и запусти проект из чистого состояния. Зафиксируй все ручные действия и найденные блокеры.
2. Составь карту компонентов и зависимостей: HTTP, БД, кэш, модель, файлы индекса. Отметь источник истины и производные данные.
3. Подготовь детерминированный seed: несколько типов пользователей, категории товаров, история доставленных заказов, новые пользователи без истории.
4. Автоматизируй smoke-сценарий: вход → каталог → заказ → рекомендации. Отдельно проверь пустой каталог и пользователя без покупок.
5. Проверь существующие тесты и инструкции README. Зафиксируй версии runtime, образы и время холодного старта.

## Эксперимент
Пересоздай контейнеры и данные из сохранённых артефактов. Определи, какие данные пережили рестарт и почему. Не используй единственный экземпляр нужных данных для разрушительной проверки.

## Приёмка и артефакты
- Новый запуск воспроизводится без ручной правки MongoDB.
- Seed и smoke повторяемы; ошибки дают ненулевой результат проверки.
- Есть карта зависимостей, список обнаруженных дефектов и точка возврата в Git.

## Подсказки для поиска
Deterministic fixtures, Docker healthcheck vs readiness, reproducible builds, seed isolation. Не считать успешный HTTP 200 достаточным: проверять тело ответа и итоговое состояние.

Рубежи: запуск → данные → smoke → повторный запуск.
