# 02. VM и межнодовая сеть

[Маршрут](../lab-sequence.md) · Нужно: 01 · Далее: [03](03-app-observability.md)

## Цель
Построить измеренную основу кластера на ПК и Legion. Топология и начальные бюджеты: [инфраструктурный план](../kubernetes-devops-labs.md).

## Задание
1. Уточни ресурсы Legion и выбери гипервизор, совместимый с Windows и WSL2.
2. Создай по одной Linux-VM на каждом хосте. Задай уникальные имена, бюджет RAM/CPU/диска, SSH и синхронизацию времени.
3. Организуй двустороннюю L3-связность. Начальный кандидат — NAT и Tailscale внутри гостей.
4. Нарисуй путь пакета: guest → Windows NAT → Wi-Fi → peer. Отметь IP/CIDR, firewall, direct/relay и будущие Pod/Service CIDR.
5. Измерь RTT, потери, пропускную способность и поведение крупных пакетов. Повтори после перезапуска гостей и хоста.

## Эксперименты
- Сравни связь в спокойном режиме и при ограниченной фоновой передаче.
- Перезапусти VPN одной VM: сохранились ли адреса и восстановились ли маршруты?
- Проверь, что выключение Legion не лишает тебя доступа к VM ПК.

## Приёмка и артефакты
- Между гостями есть устойчивая двусторонняя связь, адреса и маршруты объяснены.
- Зафиксированы direct/relay, сетевой baseline, свободный диск и поведение sleep/автостарта.
- Нет пересечения выбранных диапазонов; схема сети и настройки воспроизводимы.

## Подсказки
NAT vs bridged networking over Wi-Fi, Tailscale netcheck/ping, iperf3, path MTU, time synchronization. Скорость Wi-Fi в свойствах адаптера не равна пропускной способности между VM. Не устанавливай Kubernetes до проверки сети.

Рубежи: VM → связность → измерения → восстановление после reboot.
